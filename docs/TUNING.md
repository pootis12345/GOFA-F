# 验证集搜索与安全巡检

当前 stage1-v2 是固定默认配置的首轮实验，继续使用原快照，不回写或重跑其结果。
按用户最新要求，当前所有默认计划仅使用种子 42，43/44 暂缓。
开发默认已切换至逐数据集短历史与可核验外部空间图的协议 v2；
后续搜索继承 `configs/benchmark.yaml`，必须使用新快照、新输出目录，不能混入旧首轮结果。
来源和边界见 [骨干流程与协议 v2](MODEL_FLOW_AND_PROTOCOL_V2.md)。
任何测试分数都不得用于选择后续配置。已有默认配置的测试评价需要在最终试验次数中披露。

## 第一轮学习率搜索

`configs/tuning.yaml` 固定种子 42、继承各数据集当前注册的预测长度（`dataset_default`），
学习率 1e-5/1e-4/1e-3。显式长度列表仍仅匹配相应注册数据集。
六个数据集 × 六种可训练模型设置 × 三个学习率，共 108 组；Persistence 没有学习率，不参与搜索。
这是旧编码器机制的未启动搜索，并非 [新阶段 8 小时方案](NEXT_STAGE_PROTOCOL.md) 的运行指令；
新阶段仅做小预算位置/学习率选择，不启动这 108 组矩阵。
每种设置的候选数、最大 epoch、patience、批量和梯度累积均相同。
这是等试验次数/训练上限比较，早停的实际步数、可训练参数、耗时与计算量不保证相等。
图层位置、rank、邻居数仍固定；这些搜索以及消融、其他预测长度的设置选择尚待完成。

以下命令仅在 C 执行。先核对进程、GPU 与当前输出；stage1-v2 运行期间不并发启动搜索。
真正启动时另建固定提交的运行快照，保持共享数据和当前环境不变。

```bash
python -m gofa_f.tune --plan
python -m gofa_f.tune --output outputs/lr-search-v1
# 已完成全部候选时，只汇总验证分数，不运行训练：
python -m gofa_f.tune --output outputs/lr-search-v1 --select-only
```

每个候选强制 `evaluation_split: validation`，不构建测试窗口、测试 DataLoader 或计算测试指标。
数据加载仍校验完整 NPZ 的结构与哈希；标准化和相关图仅用训练前缀，外部空间图不使用未来观测。
外部图/元数据哈希与准备数据的绑定必须一致；不同图版本不能混入同一次配置选择。
最佳检查点的验证指标写入 `result.json`，完整验证标记为 `validated`；截断运行仍是 `smoke`。
正式 `gofa-report` 只接受 `complete`，排除上述两类结果。

输出根目录保存 `search_manifest.json`，改变网格或筛选条件必须使用新目录。
每个候选单独保存在 `lr0/`、`lr1/`、`lr2/` 子目录，索引与 manifest 对应。
完整结果可核对配置与数据哈希后跳过；中断目录保留，不能覆盖为成功结果。
仅当全部候选和全部注册种子通过，才生成 `selection.json`。
按每数据集/模型/预测长度的种子平均验证标准化 MAE 选择，平分时取更小学习率。
不同数据或代码版本、脏源码、冒烟、测试评价混入和非有限分数均不能参与选择。
固定选择后仍需生成后续正式实验配置；本工具不会自动扩大到 378 组或调用测试集。

单独运行训练或既有矩阵时也可加 `--validation-only`；完整正式评价保持默认行为。
验证模式和测试模式必须使用不同输出目录，不能相互替代已有结果。

## 进度检查

```bash
python -m gofa_f.progress outputs/stage1-v2 --expected 42
```

该命令只输出完成/验证/冒烟/未结束/无法读取的计数、已记录 PID、epoch、训练步数与最近验证指标，
不输出测试分数，不加载权重、检查点或数据数组。正在追加的末行和正在写入的结果会留待下次读取。
`incomplete` 只表示没有完整结果；进程是否存活要另用 `ps` 检查，不能据此启动重复训练。
`.status` 和结果中的 PID 也可能过期。`--expected` 必须对应所选阶段目录，不能混用旧尝试。
