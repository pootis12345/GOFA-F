# Stage6 METR-LA long-horizon protocol

This stage is a single-seed development experiment on METR-LA only: 12 observed five-minute steps to 12 forecast steps, seed 42. It starts C1 and C2 independently from the same frozen pretrained Chronos Bolt-mini checkpoint. It does not fine-tune Stage5 weights.

Stage5 validation raw MAE is 3.2724996365709145 and Stage5 test step-12 raw MAE is 4.602717. C1 adds the six available source-clock features to the five historical graph features of the Stage5 routed model. C2 adds a shared per-node `30→64→12` GELU residual network reading 12 history values, 12 observation indicators, and six known forecast-origin clock values. Its last layer starts at zero. Its output is scaled by the same per-window normalization scale as the native prediction and shifts all quantiles equally. Both variants retain the physical road graph, dynamic routing rank16, prior floor0.5, interleaving at `[1,2]`, and the private rank4 native head adapter. An eligible winner gets one freshly initialized identity-adjacency control of the same architecture.

All variants use AdamW, graph and residual learning rate 1e-3, output-adapter learning rate 1e-4, weight decay 1e-4, clipped gradient norm1, effective batch64, raw-unit observed-target MAE, max100 epochs and patience15. The smaller microbatch is selected only after an OOM; accumulation still represents 64 samples. Each epoch's sample order is fixed from seed42. Complete validation raw MAE over all 12 steps selects checkpoints and candidates. The candidates must each have a complete validation pass before selection. A candidate qualifies at or below 99.5% of the Stage5 validation MAE. If C1 and C2 are within 0.5% relative, C1 wins; otherwise the lower validation MAE wins. No test target is read by training or candidate selection. Final evaluation opens test targets only after all available best-checkpoint SHA-256 hashes have been sealed.

The [TITAN paper](https://arxiv.org/html/2409.17440) reports 60-minute MAE 3.08 at a nominal 12→12 and 70/10/20 setting. The [official model file](https://github.com/sqlcow/TITAN/blob/main/model.py) remains a placeholder. This stage verifies its own 34,272-row, 207-sensor source ordering, exact zero mask, split and step-12 metric. The 3.08 number is an external cross-implementation reference because the exact TITAN windows, normalization, masking and evaluation code cannot be verified. It is never a selection criterion.

The new fixed snapshot and output name are `stage6-metr-long-v1`. The stage refuses changed data, graph, calendar sidecar, native checkpoint, Stage5 result, runtime versions, source commit or six-hour launch window. The CPU-only launcher first records the absolute window and then waits for three strict 30-second GPU-idle observations. Every GPU subtask repeats admission. Once started, it does not stop because another user joins; the worker pauses updates while less than 16 GiB remains free. Own allocation is capped at 40 GiB, Torch at 38 GiB. No exclusive GPU setting or other-user process is touched. Training stops 15 minutes before the six-hour hard deadline; the deadline does not move after a restart. The launcher and worker maintain separate active-time ledgers and all trainable model, optimizer, RNG, sampling cursor and early-stopping state are checkpointed.

This is one seed with previously viewed development tests. A single score at or below 3.08 would not be a robust TITAN reproduction. There is no unregistered architecture, learning-rate or loss follow-up in this stage.
