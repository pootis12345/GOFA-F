# Stage7: one locked GOFA-F checkpoint across six datasets

This development evaluation fixes the Stage5 METR-LA routed GOFA-F checkpoint before opening any target validation or test predictions. Its SHA must equal the Stage5 final-selection record. The same private graph and rank-4 output-adapter tensors are loaded without changes for METR-LA, PeMS-BAY, AQI-437, AQI-36, Electricity and Solar-Energy; the frozen Bolt-mini weights also remain identical. No target gradient updates, checkpoint selection or target-specific hyperparameter tuning occur. Each target retains its previously registered history→horizon task, chronological split and audited physical/geographic or training-only correlation graph.

The target's observed training prefix provides the existing standardization and pooled level/scale used to form five causal graph features. This makes the experiment **calibrated weight transfer**, not cold-start zero-shot forecasting. Distinct target graph buffers and normalization statistics are inputs rather than learned checkpoint changes. The first target is METR-LA itself; its complete validation MAE must reproduce the Stage5 result before any transfer target is evaluated. All six targets receive full validation and test metrics; these are descriptive and never used to change the source checkpoint. Previously viewed development tests, one seed, AQI-437/AQI-36 overlap and unequal tasks remain limitations.

Before deployment, C runs a CUDA-disabled six-target real-weight CPU forward check. The fixed snapshot binds source code, the Stage5 result and checkpoint hashes, six prepared datasets and graph files, native weights, environment versions and an eight-hour absolute wall window. The CPU supervisor and every new GPU evaluation task require three consecutive 30-second strict-idle samples: no compute/graphics processes, 0% utilization, at most 256 MiB driver memory and Default compute mode. A query failure keeps it waiting. Once admitted, another user joining does not stop the task; low available memory pauses work. Own allocation is capped at 40 GiB, Torch at 38 GiB, with at least 16 GiB reserved for sharing. Waiting does not extend the wall deadline. No exclusive mode or other-user process is changed.

The output records each target's original-unit MAE, RMSE, MAPE valid fraction, WAPE and horizon metrics, source checkpoint SHA, parameter counts, zero target updates, activity time, CUDA peaks, any failure and the stopping reason. A target interrupted mid-evaluation is rerun from its unchanged source checkpoint; completed atomic results are reused. Stage5 and Stage6 outputs and snapshots remain untouched.
