# ChatTime–GOFA：末尾层图交织与未见数据集预测

## 已确认的研究重点（2026-10-17，Asia/Shanghai）

用户要求将后续研究重点改为：把 ChatTime 改造为类似 GOFA 的末尾 LLM 层与
GNN 层交织结构，以 ChatTime 原论文表4的任务评价。用户进一步明确：
**不在这八个数据集上训练。**

八个目标数据集为 ETTh1、ETTh2、ETTm1、ETTm2、Electric、Exchange、Traffic、Weather。
不使用它们的任何划分更新骨干、图模块、编码器、路由、预测头或其他参数；
也不通过这些目标集的验证/测试成绩选择结构、学习率、早停点或检查点。
超参数与检查点选择只使用独立源数据的训练/验证集。
同一新模型检查点评价所有目标数据集与历史长度，不逐目标集切换权重。

这是后续研究方向与验收边界，**不是已完成的新模型或已启动的新实验**。
旧阶段结果保留；Stage16 固定快照、运行和既定截止不因本次文档更新改变。
Stage16 的连续回归头和 METR-LA 监督结果不能冒充本方案的原生生成或表4零样本结果。

## 评价任务

依据 [ChatTime 论文表4及第4.2节](https://arxiv.org/html/2412.11376#S4.SS2)，
每个数据集有四种历史长度，共32种设置，指标为 MAE，时间划分为60/20/20：

|目标数据集|历史长度|预测长度|
|---|---|---:|
|ETTh1、ETTh2|48、72、96、120|24|
|ETTm1、ETTm2|192、288、384、480|96|
|Electric|48、72、96、120|24|
|Exchange|14、21、28、35|7|
|Traffic|48、72、96、120|24|
|Weather|288、432、576、720|144|

Traffic 是小时级862路段占有率数据，不是 METR-LA。
Electric 与旧项目 Electricity 的版本/来源须核验，不能因为名称不同而当作独立源数据。
ETTh/ETTm 的不同分辨率和同源转换版本都归入排除范围。

仍须核实作者释放样本的来源、时间起点、变量 ID、采样步长、评价尺度、缺失规则、
目标变量覆盖和聚合权重。论文表中数字不是自动可比的本项目实测成绩。
若释放的 Hist/Pred 行缺少对齐信息，应使用可核验的原始多变量序列恢复图样本；
不能把无关的一维切片行任意拼成同时刻的邻居。
若不能恢复完全相同的样本集合，必须标记为表4任务的独立重评，不能称严格数值复现。

## 新架构的必要条件与建议实现

必要条件：保留 ChatTime 官方 tokenizer、数值离散化/反离散化、提示和语言输出头；
图消息插入末尾连续 Transformer 层之间，最终仍从原语言输出头自回归生成数值 token。
不以 Stage16 的4096→12连续头作为主预测路径。
冻结已有 ChatTime 权重，先仅在独立源数据上训练新增图侧参数。
生成式训练对回答 token 使用因果 next-token 交叉熵，提示 token 不作为目标；
验证必须真实生成并计算数值误差，不能用 teacher-forced 训练损失替代预测成绩。

建议以零起始层[29,30]作为首个固定布局，保留最后一层 Transformer。
效率方案可采用“目标变量经过 ChatTime、辅助变量历史经过共享轻量时序编码器、
图消息注入目标的末尾层”，但这属于 GOFA 启发的目标读出变体，
不能声称与原 GOFA 所有节点均由 LLM 编码的结构完全相同。
具体图侧结构和参数预算须在源数据验证之前另行固定，不用目标集成绩搜索。

图节点对应有同步历史的变量，参数跨变量和数据集共享，不依赖固定节点总数或目标节点 ID。
目标图由当前可见历史构建，或使用预先可获得、未由目标数据拟合的外部拓扑。
目标集的训练段也不得用于拟合相关图、标准化统计或可学习节点嵌入；
历史窗口缩放遵循 ChatTime 的历史限定协议。图编码与邻居信息不能读取未来真实值。
训练时 teacher forcing 的目标未来 token 不得流入辅助节点历史缓存或构图路径。

推理需正确维护被图消息修改后的后缀 KV；不能沿用未修改原生后缀的 KV 假称等价。
初始零图增量应与原生模型 logits/生成一致，新增分支应能获得有限梯度。
纯文本绕过图模块可检查原生功能保留；这不能替代图条件语言问答的能力评价。

只让一个目标变量经过 LLM 可以降低单目标计算量；评价表4时仍须覆盖作者协议规定的
目标变量，不能只挑一个容易的变量并称完整表4成绩。
逐目标覆盖全部变量仍需要多个 LLM 前向，因此不预先承诺整套任务获得节点数倍提速。

## 源数据与零样本隔离

源数据清单必须记录原始来源、哈希、变量、时间范围、派生关系和八个目标集的排除检查。
旧 METR-LA、PeMS-BAY、AQI 或 Solar 数据可审计为候选源；这不是已确定或已通过的源清单。
旧 Electricity 在来源核验前排除。Monash/TFB 也须逐子集排除八个目标及其重采样、别名和副本。
源数据须提供真正对齐的多变量历史，不能默认现成单变量预训练切片含有可恢复图结构。
目标测试集只在源验证锁定模型、数据协议、解码与 SHA 后读取。
目标60%前缀不训练也不拟合；仅当它位于某个合法预测起点的历史窗口内时作为观测输入。

## 对照、解码与验证

主对照仅原生 ChatTime 与生成式 GOFA-F(ChatTime)，同一官方权重起点、历史、提示和解码。
原生模型不在目标数据上训练；新图模型也不进行任何目标适配。
官方 [预测实现](https://github.com/ForestsKing/ChatTime/blob/8c2d4c209302d2b2bd6cc3c154586842341e3247/model/model.py)
默认8次采样取逐点中位数，并以最多16个数值为块滚动延长历史后继续生成。
正式作者协议对照应复核并沿用该流程；若采用贪心以节省开发成本，两组必须一致，
单列为解码协议变体，不能与论文表值混为同一次复现。
长预测任务不能沿用 Stage16 的固定64新 token 上限而截断输出。

CPU/GPU 验证须覆盖：源/目标隔离、构图因果性、异构节点数、批次隔离、
原生生成初始一致、冻结梯度、teacher-forcing 掩码、增量 KV 与非缓存生成一致、
缺失与常数历史、语言绕过、准确恢复，以及完整预测覆盖。
失败生成的处理预先固定，报告覆盖率与回退，不丢弃失败样本美化指标。

纯图基线可在后续作为补充，但目标集训练的 GNN 属于 full-shot 参照，
不能与源数据训练的模型混称相同零样本协议。
表4不包含语言问答，语言交互和图条件解释需要独立保留性/能力检查。

## 执行边界

先完成源数据与目标协议审计，再固定独立配置、代码、恢复清单及快照，才部署新阶段。
新模型训练不复用 Stage16 连续头或已训练图参数作为未经登记的初始化。
B编辑和静态检查，C禁CUDA、OMP/MKL各2线程验证；GPU继续遵守用户最新
memory_cap_only策略：项目进程组40GiB、Torch38GiB，不等待完全空闲，不操作他人进程。
本次不自动新增GPU作业、修改既有Stage16快照或延长其21:30训练/23:30硬截止。

主要待完成项：可核验的独立图训练源、官方表4样本与尺度、生成式图交织与KV实现、
源数据验证锁定和32种完整目标评价。旧阶段成绩不能补填任何未运行的新结果。
